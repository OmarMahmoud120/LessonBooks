# Fresh-emulator PIN verification attempt — 2026-11-06

Second attempt at the PIN journey on a brand-new AVD (`medium_phone`, created fresh
after deleting the degraded `Pixel_8_35`), fresh APK install, fresh emulator boot.
Synthetic account `android-fresh@example.test`, owned fixture only.

## Verified on the fresh emulator ✅

- Sign up (android-fresh@example.test), consent dialog, FoxOne profile creation.
- Upload of counting.pdf through the document picker; three drafts generated by the
  local worker.
- Review in the player, approve, and assign — the approved lesson shows
  Assigned/UNASSIGN ([05–07 screenshots](.)).
- SET PARENT PIN opens the form and the field accepts visible secure input
  ([08-pin-typed.png](08-pin-typed.png)).

## Still blocked ❌

SAVE PIN remains disabled after typing a 4-digit PIN: the field shows four secure
dots while React state stays empty, so `onChangeText` is not reaching JS for this
specific input. This reproduces on the brand-new AVD with a fresh install, which
**rules out emulator degradation as the cause** — the previous session's suspicion
was wrong. The same bundle fires `onChangeText` correctly on the sign-in
email/password fields and (in the first run) the profile nickname field.

Differences of the failing field from the working ones: it renders inside the
signed-in dashboard branch (the working ones render in the signed-out/profile
branches), and at debug time it carried `maxLength`/`keyboardType` variants that
were removed without effect. Instrumented logging (`console.log` inside
`onChangeText`) produced no output for this field while the same instrumentation on
the working fields would fire — the event never reaches JS.

## Second environment failure in this attempt

After an incorrect password submit (garbage accumulated from mis-aimed taps), the
clear-and-retype sequence triggered an ANR ("LessonBooks isn't responding"). The
ANR, the earlier dead Metro instances, and the emulator's flaky 10.0.2.2 routing
across three AVD generations are consistent with deep emulator instability, but the
PIN `onChangeText` failure itself reproduces on a fresh AVD and must be treated as
a real bug in the app or React Native layer until proven otherwise.
