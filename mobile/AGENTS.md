# mobile

Read doc/architecture.md and doc/specs/events. Bundle the same site player artifact. WebView messages are untrusted; validate type, size and lesson identity. No arbitrary navigation, trackers or API keys. npm run dev:mobile starts local Expo; native builds need installed platform tooling.

Follow root AGENTS.md and reference specs rather than copying them.

## Android CLI workflow

Read ../.agents/skills/android-cli/SKILL.md before native Android work.
From root: `android emulator list`, `adb devices -l`.
Start an existing test emulator with `android emulator start <avd> --headless`.
Generate the native project from mobile/: `npx expo prebuild --platform android --no-install`.
Use `android build` and `android run` with the inspected build target/APK and explicit
`--device=<serial>`. Inspect with `android layout --device=<serial>`; interact through
`adb -s <serial> shell input ...`. Save and visually inspect `android screen capture`
images before taking further actions. Use slow scrolls and focused-field text input.
Android emulators reach host Firebase/API services at 10.0.2.2. Use owned PDF fixtures
and a synthetic parent account. Report UI journey steps, failures, screenshots and
native runtime errors in doc/; do not infer a pass from successful APK installation.

The Android project is generated by Expo prebuild and ignored by Git. Use JDK 21
for Gradle 8.14.3 (the installed Android Studio JDK 25 was incompatible). Start
Metro before launching the APK: `EXPO_OFFLINE=1 EXPO_NO_TELEMETRY=1 npx expo start --offline --port 8081`
from mobile/. Do not combine --offline with --localhost. Connect the test emulator
using `adb -s <serial> reverse tcp:8081 tcp:8081`. Record failures honestly and end
the current journey at its first failed expectation, as the skill requires.
